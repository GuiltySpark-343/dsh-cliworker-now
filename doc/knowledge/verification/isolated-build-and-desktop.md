# 先构建隔离包，再更新 Desktop

开发中的构建应先落在隔离目录，避免改写运行中的 Desktop 已链接产物。

## 机制

`build:preview` 将源码、必要构建脚本、包声明和随包原生资源复制到 `.cache/preview-package`，连接选定的依赖目录，再在该目录执行构建。它隔离构建输出；正式 `build` 会写仓库自己的产物，不能在 Desktop 仍链接这些产物时随意执行。

隔离包构建成功后，还要在独立 profile 或目标测试环境核对实际安装来源。Desktop 更新前确认没有活动 Worker，并正常退出宿主；通过受支持的安装入口更新，冷启动后核对真正加载的版本与产物。设置、原生会话、密钥及不相关配置需要保留。

## 边界

- 隔离输出不等于操作系统沙箱；不要把 preview 包链接进用户正在使用的会话环境后继续覆盖它。
- 构建通过不等于安装成功，安装成功不等于新代码已被当前进程加载。
- 正常退出／冷启动、安装回执及包内容核对共同支持“更新已生效”。旧窗口继续运行时，不能仅凭磁盘文件推断运行版本。
- 本地修改、构建与安装不自动授权 GitHub 提交、推送或发布；版本规则以当前项目约定为准。
