# Qoder 在同一目录操作内共享一次元数据读取

当目录核验同时需要账号和模型，复用同一次原生读取可以减少重复启动，也能避免两次查询看见不同的来源；共享范围必须止于本次目录操作。

`withQoderCatalogSnapshot()` 使用 `AsyncLocalStorage` 建立查询作用域，限定同一 backend、配置、可执行文件、项目和取消信号。`scopedMetadata()` 将第一次读取的 Promise 保存在作用域内，后续消费者等待同一结果并获得副本；失败清除该 Promise，作用域结束后清空读取状态。这是操作内的 single-flight，不是跨窗口、跨账号长期缓存认证。

进入和离开作用域都计算来源证明，覆盖原生账号文件、机器标识、设置、项目环境、自定义模型目录清单及相关文件摘要。不存在的来源也进入证明，自定义模型新增或路由环境变化可以被发现；前后不一致则拒绝结果。原生查询的结束会话、进程退出和临时目录清理先于消费者使用结果。

模型元数据查询采用隔离的临时原生目录，保留必要的当前来源并避免复制历史或默认模型缓存。这个优化不能承诺“任何 CLI 读取都完全无副作用”：应检查各 CLI 的实际查询实现，也不能把真实任务的 ACP 会话和元数据读取协议混为一谈。
