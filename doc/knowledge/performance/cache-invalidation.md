# 缓存复用由来源代际控制

缓存性能依赖明确的失效规则。账号、可执行文件、项目或宿主变化后，旧目录不能因“之前查到过”继续支配当前选择。

Host 的 `SettingsCacheMetadata` 包含策略版本、Host 随机代际、项目摘要、每 CLI 来源版本、目录证明是否仍在，以及当前项目偏好。`cliSettings()` 只读取这些元数据，不为了核对展示缓存启动 CLI。Client 比较作用域：Gateway、Host、项目隔离；单个 CLI 来源版本变化或被禁用，只清除该 CLI 的账号、目录和旧草稿。Host 换代则清空该连接的旧池及保存状态。

轻量元数据不会持续监视原生账号或配置文件。插件内的开关、路径及账号操作会推进相关代际；从外部终端换账号或改配置后，设置页可能暂时保留旧摘要，需要主动刷新重新发现。保存和发送仍执行实时核验，展示复用不允许错账号执行。

每个 CLI 还有本地递增代际，查询开始时捕获版本，结束时版本不一致就丢弃。缓存不仅需要判断“现在该不该用旧值”，还需要阻止失效前发出的请求在失效后重新发布旧值。手动账号刷新随后强制刷新目录，避免账号状态更新而选型仍属原来源。

`catalogReady` 表示当前 Host 是否仍有内存目录绑定证明；缺少证明会丢弃模型展示，但不据此中止已经正常提交的偏好保存。元数据只是展示范围标识，不能替代原账号绑定；设置保存和任务执行仍走各自的实时核验。
