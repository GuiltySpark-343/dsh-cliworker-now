# worker-conversation-interaction Specification

## Purpose

保证 CLI Worker 子对话的阅读、消息操作和续聊提交遵循 Harness 主聊天的原生交互，继承原生主题并保持 Worker 的会话身份、草稿和执行权限，使用户在两个聊天区使用一致的操作习惯。

## Requirements

### Requirement: 原生返回最新交互
子对话 SHALL 使用与 Harness 0.2.0-rc.2 一致的圆形向下图标、主题和交互反馈返回最新消息。离开底部时按钮出现，回到底部时隐藏；更新到达时 MUST 保留历史阅读位置，点击后恢复跟随。原生未提供入出场或平滑滚动时不得自行新增。

#### Scenario: 历史阅读与返回
- **WHEN** 用户向上滚动且新消息到达
- **THEN** 保留当前阅读位置并显示圆形图标按钮，点击后立即回到底部并恢复新消息跟随

#### Scenario: 主题与可访问操作
- **WHEN** 用户切换原生主题或使用键盘操作返回按钮
- **THEN** 按钮继承原生主题参数，具有必要的可访问名称和原生反馈，不新增文字条或占用对话高度

### Requirement: 原生消息功能条显示
最新用户消息 SHALL 保留功能条；最后一轮以可见 AI 回复结束时，该回复功能条 SHALL 保留，已隐藏的完成空回复不改变此判断。支持悬停的设备上，更早消息的整条功能区 SHALL 在对应原生范围悬停或包含键盘焦点时显示，透明度动效与原生一致，布局保持稳定；触屏保持显示。透明度隐藏 MUST 保留键盘可访问性。

#### Scenario: 历史消息与末条消息
- **WHEN** 子对话已有多轮用户消息和 AI 回复
- **THEN** 最新用户消息常显；最后一轮以回复结束时该 AI 功能条常显，更早功能条在原生消息或回复尾部范围悬停或聚焦时显示

#### Scenario: 新回复和历史页
- **WHEN** 新消息成为最新消息，或用户翻到较早历史页
- **THEN** 原最新消息回归历史显示规则，历史页不得把仅因分页显示的末条误判为真实最新消息

#### Scenario: 最终正文之后有空完成步骤
- **WHEN** 有正文的最后回复之后仅有隐藏的完成空步骤
- **THEN** 该正文功能条保持常显，后续真实用户或工具消息仍遵守原有边界

### Requirement: 原生输入提交规则
可续聊的输入框 SHALL 按 Harness 0.2.0-rc.2 的 Enter、Shift 和修饰键规则提交或换行，并保护组合输入及原生确认后的短窗口，重复按键不得重复发送。空闲时提交 SHALL 经过现有 Worker 续聊入口；忙碌时 SHALL 按点击时固定的项目与 CLI 发送偏好处理，允许继续编辑输入。输入框右下角 SHALL 仅有一个动作按钮：运行中无正文时为停止，有待发正文时为发送，停止清理中无正文时显示禁用的停止，有正文时仍为发送并按固定方式等待清理。保持空白、断连、权限和草稿保留规则；正常停止且已确认清理的会话按停止恢复规则继续可用。

#### Scenario: 发送与换行
- **WHEN** 可续聊 Worker 的输入框含有文本，用户按普通 Enter 或原生支持的 Ctrl/Cmd+Enter
- **THEN** 空闲时提交一次，运行时按选择的引导、插队或排队处理；Shift+Enter 保留换行，原生不支持的组合键不提交

#### Scenario: 中文输入法与长按
- **WHEN** 按键处于组合输入、原生确认后的保护窗口或为重复键事件
- **THEN** 不发送消息；组合输入完成后正常 Enter 可以提交

#### Scenario: 不可续聊与失败
- **WHEN** Worker 断连、空闲但缺少会话且不符合正常停止恢复条件、文本为空或提交失败
- **THEN** 不通过快捷键绕过限制，未成功提交的文本保留且不覆盖新草稿，不向主聊天发送文本

#### Scenario: 准备和清理也占用会话
- **WHEN** 第一条提交尚在本地、Host 准备、等待启动、运行或停止清理，用户再次发送
- **THEN** 同步判定忙碌并按本次模式固定去向；排队立即显示卡片，插队立即显示气泡，引导未就绪则保留草稿并明确拒绝，不静默改道

### Requirement: 完成的空回复只在过程区展示
已完成且没有正文或其他可见内容的 assistant 步骤 SHALL 不生成独立聊天消息块，统计和时间 SHALL 保留在可展开过程区，不改写历史事件。空字符串和纯空白等价；活动流式输出、公开工具、错误以及有正文回复 MUST 保持可见，不为此重跑任务。

#### Scenario: 空白和仅统计的 DONE 步骤
- **WHEN** DONE assistant 的正文为空或纯空白，包括只有 Token 和耗时的步骤
- **THEN** 不出现空白聊天块，展开过程仍可查看其统计，累计不丢失且不重复相加

#### Scenario: 流式与错误
- **WHEN** assistant 正在流式输出，或本轮有工具与错误记录
- **THEN** 保留当前流式展示及工具和错误；流式收到正文后正常渲染，已结束空输出仍有本轮过程和终态

### Requirement: 当前轮结束后自动发送
以排队方式提交的消息 SHALL 按各自提交顺序和暂停状态保存在所属 Worker 的待发送队列，可查看、取消和插队；标题下有分隔线，列表支持带动效折叠，关闭侧栏或折叠不影响等待。仅在上一轮正常完成且进程范围清理确认后 SHALL 沿原生会话逐条执行，并重新验证当前权限、账号、模型及强度。队列不是即时引导，不得显示为已送达 CLI。

#### Scenario: 多条消息与关闭侧栏
- **WHEN** 用户在当前轮期间排队两条消息并关闭侧栏
- **THEN** 显示为待发送，Host 仍按先后顺序在每轮正常完成后启动下一条，不并发运行同一会话

#### Scenario: 异常与停止
- **WHEN** 前轮失败、结果待核实、停止、缺少会话或清理未确认
- **THEN** 保留未发送消息并暂停自动执行，明确显示原因，必须经用户再次操作才允许继续；用户本次明确发起的插队可在停止清理确认后发送所选消息

#### Scenario: 重启与取消
- **WHEN** Host 重启或用户取消待发送消息
- **THEN** 重启恢复未发送文本但不自动执行；取消成功的消息不再执行，已开始的消息只能使用停止操作

#### Scenario: 归属与重复请求
- **WHEN** 请求属于其他父会话、引用过期执行准入或是同一提交的重复请求
- **THEN** 拒绝越权和过期准入动作，重复请求不产生重复轮次；明确排队按所属 Worker 及消息 ID 受理，前轮自然结束不拒绝该队列请求；派发和停止竞争时不能绕过停止

#### Scenario: 折叠待发送列表
- **WHEN** 用户展开或收起待发送列表
- **THEN** 保留标题与数量，列表高度和透明度平滑过渡；收起后内部操作不可键盘聚焦，减少动态效果偏好下无过渡，实际队列继续按原规则执行

#### Scenario: 待发送卡片外观
- **WHEN** 待发送卡片与输入框同时显示
- **THEN** 两者使用相同圆角、底色、阴影及描边；标题分隔线贯穿卡片左右边缘，条目分隔线左右内缩；插队和取消在条目高度内垂直居中

#### Scenario: 停止后新轮的独立队列
- **WHEN** 用户主动停止使旧队列暂停，随后明确发起新轮并排队新消息
- **THEN** 旧暂停消息仍保留暂停；新消息跟随新轮在正常完成且清理后执行，不继承旧队列暂停，也不自动恢复旧消息

#### Scenario: 队首准备与准入
- **WHEN** 队首已预留但仍在复核，或此时用户取消、插队或继续排队
- **THEN** 队首准备占用会话，新消息排在正常队尾；准备失败保留卡片暂停，只有唯一原生启动准入后转为一个气泡，已准入不得伪装取消或重放

### Requirement: 展示原生公开过程
过程区 SHALL 按 Harness 0.2.0-rc.2 原生展开体验展示已支持协议明确公开的思考摘要、计划和工具记录，复用可用原生组件与主题，保持折叠行、Markdown、工具树、结果及状态的格式、交互和键盘体验；注明来源与内容性质，摘要留在过程区而非最终回复。未公开、redacted、签名或加密内容 MUST 不被提取或当作可读思考，不生成替代内部推理。

#### Scenario: 公开摘要与重复快照
- **WHEN** 受支持 CLI 提供公开摘要事件及其完成快照
- **THEN** 过程区展示同一摘要的当前内容而不重复，最终正文和任务成功判定不受摘要影响

#### Scenario: 没有公开摘要
- **WHEN** CLI 仅提供工具、状态或没有可读摘要
- **THEN** 展示实际已有记录；没有公开内容时不添加正文缺失提示，不显示伪造内容或把私密字段当摘要

#### Scenario: 思考和工具使用原生展开体验
- **WHEN** 用户展开有公开思考、计划或工具调用的 Worker 过程
- **THEN** 内容按真实顺序呈现，思考使用原生 Markdown 格式，工具调用和结果支持原生样式展开，状态和耗时继承本轮真实值；不保留替代原生内容的大段原始 JSON 卡片或英文内部状态标签

#### Scenario: 工具参数和结果不可信
- **WHEN** 原生工具返回命令、路径、结构化参数、终端结果、差异或 HTML 字符串
- **THEN** 按已确认类型使用安全的原生展示组件及折叠规则，未知内容作惰性文本或结构化数据，不执行 HTML，不捏造工具层级、文件差异或调用关系

#### Scenario: 中断、恢复和窄栏
- **WHEN** 过程流式更新、正常停止、重开历史或在窄侧栏及减少动态效果设置下查看
- **THEN** 保持真实展开/收起与滚动边界，停止不把未完成工具改写为成功，回复正文不被过程碎片或状态说明撑开，既有排队与独立引导行为不变

### Requirement: 运行中发送偏好
高级设置 SHALL 通过原生下拉框提供“引导、插队、排队”，按项目与 CLI 独立保存，选后自动保存。按实际 transport 已接通并确认原生引导的通路默认引导，其余默认排队且禁用引导；用户授权本次将现有项目设置一次性按能力更新，此后手动保存优先于默认。打开设置 MUST 不启动 CLI 或写入偏好，保存失败显示错误并允许重试，现有设置与历史数据兼容。

#### Scenario: 能力默认与持久化
- **WHEN** 用户首次打开已确认支持原生引导的 CLI 高级设置，或不支持引导的 CLI 设置
- **THEN** 分别显示引导或排队，保存插队后重新打开同一项目与 CLI 保持插队，其他项目与 CLI 不受影响

#### Scenario: 不支持和失败
- **WHEN** 当前通路不支持原生引导或保存失败
- **THEN** 不允许选用不支持的引导，保存失败保留选择及错误；不会静默执行其他模式

#### Scenario: 暂停卡片的选型保持
- **WHEN** 所属 Worker 仍存在待发送卡片，包括暂停项，用户尝试修改模型或强度
- **THEN** MUST 明确要求先发送或取消这些卡片，保留已有选型，不将新设置追溯至旧消息

#### Scenario: 设置不追溯既有提交
- **WHEN** 消息已提交或排队后用户改变发送设置
- **THEN** 已提交消息保持点击时模式与身份，新设置只影响后续提交；历史 transport 不因新 CLI 能力被静默改换

### Requirement: 原生运行中引导
引导 SHALL 使用独立于普通排队的当前运行输入通路，不进入待发送队列，不继承队列代际、暂停、队首或自动续跑规则。引导 SHALL 将消息交给当前原生 CLI 运行，界面点击后立即显示同一用户消息并清空本次草稿，在明确接收回执后确认原生送达，不停止或重启当前轮；同一请求不重复投递。通路尚未准备或已结束 MUST 在投递前保留草稿并明确拒绝；原生拒绝或确认超时 MUST 反馈真实状态并提供内容恢复入口，不静默改为排队或插队。接收回执不代表模型已执行指令。

#### Scenario: 引导与排队独立
- **WHEN** 当前原生运行可接收引导，普通队列存在等待回执或旧暂停项，或者另一条引导正在等原生接收回执
- **THEN** 引导直接使用当前 run 的独立入口，不等待普通队列准入或其他本地引导 ACK；仍遵循原生输入语义，绝不变成下一轮待发送卡片

#### Scenario: 旧引导不阻塞已确认的新轮
- **WHEN** 旧引导接收结果未知，而 Host 已确认旧轮退出并准入新的 runId
- **THEN** 保留旧消息的未知记录和手动内容恢复，不自动重投或迁入新轮；旧引导不再阻止新轮的排队或引导，迟到回执只更新旧消息

#### Scenario: 引导目标结束
- **WHEN** 当前目标 run 未就绪、正在停止或已经结束
- **THEN** 保留未投递输入并明确说明，已经投递但回执未知时保留核查状态；不等待清理后自动发往下一轮，也不采用普通队列恢复逻辑

#### Scenario: 原生接收
- **WHEN** 已确认支持引导的当前原生运行接受消息
- **THEN** 当前运行和原生会话保持不变，消息按原生语义处理，重复同一提交只显示一次

#### Scenario: 权限与运行竞争
- **WHEN** 引导请求来自其他父会话、过期轮次、已停止任务，或当前权限及账号校验不通过
- **THEN** 拒绝投递并保留草稿，不发送给其他运行或账号

#### Scenario: 双向协议不是引导证据
- **WHEN** CLI 只有双向 stdio/HTTP、普通会话追加或下一轮排队，缺少当前运行追加输入及明确回执
- **THEN** 不声明支持引导、不启用默认引导；原生拒绝或结果不明不转为排队/插队、不盲目重投

### Requirement: 显式插队发送
插队 SHALL 将新消息或所选待发送卡片立即移入对话并平滑移出卡片，不等待停止、排队回执或准备。连续插队 SHALL 由最新请求替换此前尚未实际执行的插队请求，正常被替换或停止的消息持久保留在对话且不显示例行取消尾文，不回到卡片、不再执行；后台迟到回执不得撤销此结果。已执行的前轮仍须停止并确认进程范围退出，再验证权限、账号及选型。普通未选队列保留原顺序，已暂停队列不被无意恢复。同一 Worker 的原生执行 MUST 串行；显式停止、重复点击、过期请求和清理不确定不得造成额外派遣。

#### Scenario: 队列卡片插队
- **WHEN** 用户对第二条待发消息选择插队
- **THEN** 当前轮停止并清理后先执行该消息，其余消息文本保留且顺序不变；不会同时运行两轮

#### Scenario: 插队中停止或失败
- **WHEN** 插队等待清理期间用户停止或取消所选消息，或清理和再次授权失败
- **THEN** 不启动该消息，消息仍留在对话；正常停止无例行尾文，真正失败保留原因，不回到待发送卡片；显式新操作须再次验证权限和清理状态

#### Scenario: 即时插队与退场
- **WHEN** 用户点击插队而后台停止及准备尚未完成
- **THEN** 用户消息立即显示，所选条目高度与透明度平滑退场；最后一条退出时整个待发送区域平滑收起；用户仍能编辑后续消息，已退出项不可再次操作，减少动态效果时立即完成过渡

#### Scenario: 插队受理后准备失败
- **WHEN** 插队已受理但后续准备失败，或收到明确拒绝
- **THEN** 消息留在对话内并显示真实原因，不恢复成待发送卡片；其他卡片保留原顺序，未知传输结果须核对或停止，不自动重复执行


#### Scenario: 连续插队尚未执行
- **WHEN** 用户连续点击 A、B、C 插队，旧请求仍在停止、元数据准备或等待执行位置
- **THEN** 每次点击都立即显示相应用户消息；后来的请求取消前面尚未执行的插队，只允许最新有效请求进入原生执行；A、B 保留气泡且不显示例行取消提示、不回卡片

#### Scenario: 前次已经开始执行
- **WHEN** 新的插队到达时前次插队已开始原生执行
- **THEN** 先正常停止并完成清理后执行最新请求；保留前轮真实运行及中断记录，不把已经执行的内容改写为未执行取消

#### Scenario: 排队回执尚未到达
- **WHEN** 用户对刚加入待发送、尚未收到排队回执的消息点击插队
- **THEN** 立即转入对话，不必等待回执；迟到的排队成功或失败不能重建卡片、覆盖草稿或重复投递

#### Scenario: 历史恢复与请求乱序
- **WHEN** 用户关闭重开子对话、Host 重启，或旧插队请求及回执晚于更新请求到达
- **THEN** 已受理消息及取消记录保留，取消文本不会自动执行；旧请求不能覆盖同一来源后一次插队，未知或重启中断的请求保留真实状态等待明确处理

#### Scenario: 停止边界后的新消息
- **WHEN** 用户主动停止之后又明确发送，旧停止回执或准备结果较晚返回
- **THEN** 旧操作仅撤销停止前未执行的提交；新消息不被迟到回执取消，在旧范围清理确认后按其固定模式处理

### Requirement: 正常停止后继续对话
用户停止或插队触发的停止 SHALL 在确认进程范围清理后作为正常中断显示，不渲染为错误或归入异常筛选，不使聊天窗口永久不可用。已有原生会话 ID 时沿原会话续聊；正常停止且尚未取得 ID 时 SHALL 允许在原 Worker 建立新原生会话并明确提示。真正故障、超时、账号和权限异常、清理未确认 MUST 保持原有限制，不伪装为用户停止。

#### Scenario: 停止和插队后的输入
- **WHEN** 用户正常停止或点击待发送卡片插队且清理确认
- **THEN** 本轮显示正常停止；普通再次发送能够启动下一轮；插队所选消息按规则执行，其他暂停队列仍等待明确操作

#### Scenario: 会话建立前停止
- **WHEN** 正常停止发生在取得原生会话 ID 之前
- **THEN** 用户仍能输入并发送，界面说明将建立新 CLI 会话，不假装恢复未建立的上下文，原历史记录保留

#### Scenario: 故障与停止竞争
- **WHEN** 停止前已经发生真正失败，或停止后进程清理无法确认
- **THEN** 保留真实故障或清理阻塞；不得因用户点停止而清除风险并放行新轮

### Requirement: 立即提交反馈
用户消息下 SHALL 不显示例行的“正在发送”“已提交，等待同步”“已被后续插队取消”或“已停止发送”文字及空占位；本地展示不代表 CLI 已经接收。用户提交有效文本时界面 SHALL 立即清空该次草稿并显示待确认用户消息，排队模式显示待发送卡片；不等待 CLI 准备、metadata 或原生回执才反馈。待确认不是已送达，确认后 MUST 对账避免重复。输入仍可编辑；同一 Worker 的准备和发送保持串行，不能因解除界面等待而并发启动。失败文本可恢复或重试且不得覆盖后来输入。

#### Scenario: 慢速准备与再次输入
- **WHEN** 发送后后台尚未完成准备，用户继续输入或发送
- **THEN** 第一条立即显示并清空原草稿，后续草稿和提交保留；同一 Worker 串行准入，单按钮支持停止准备，不把同一消息重复执行

#### Scenario: 确认和失败
- **WHEN** Host 确认、拒绝或连接中断
- **THEN** 确认消息仅显示一次；拒绝文本可恢复或重试且不覆盖新草稿；不确定状态不声称成功或无条件重发

#### Scenario: 切换 Worker
- **WHEN** 用户发送后切换 Worker，再收到成功或失败
- **THEN** 仅更新原 Worker 的提交状态和草稿，当前 Worker 的输入与提交能力不被全局等待锁住

#### Scenario: 同步占用与稳定身份
- **WHEN** 连续提交 A、B 或两条相同正文，第一条准备尚未同步运行状态
- **THEN** 第一次点击同步登记占用和唯一消息身份，后一次立即按忙碌分类；同文不同操作分别保留，同一操作重试按身份去重，迟到回执不改变气泡/卡片归属

### Requirement: 气泡正文独立决定宽度
用户气泡 SHALL 只按正文计算宽度并遵守原有最大宽度，时间、复制功能条和反馈区域独立布局；MUST 保留用户正文空格、换行及原文，不用改写文本修复布局。正常发送、被替换和停止的例行反馈不生成占位；真实失败和未知结果保留可处理入口。

#### Scenario: 短正文与长取消状态
- **WHEN** 短消息处于待确认、已被后续插队替换或正常停止状态
- **THEN** 气泡保持正文所需宽度，尾部不出现例行提示或空白占位，时间和复制不撑宽正文

#### Scenario: 失败、窄屏和空白
- **WHEN** 消息包含连续空格或换行、遇到真实失败/未知结果，或在窄屏显示
- **THEN** 正文原文不变、气泡不溢出，反馈独立换行并提供恢复入口；功能条仍遵守原生显示和键盘规则

### Requirement: 内部模型目录与主对话隔离
插件 SHALL 让内部 CLI 子会话仍能解析其准确模型路由，同时不将 Worker 内部模型公布到普通主对话模型目录。侧栏选择 SHALL 仅使用当前 Worker 所属 CLI 的真实目录，打开或切换侧栏不得污染父会话选型。

#### Scenario: 普通主对话打开模型菜单
- **WHEN** 已有一个或多个 CLI Worker，用户打开主对话模型选择菜单
- **THEN** 不出现 CLI Worker 内部模型组或 Worker 实例模型，普通宿主模型保持可选。

#### Scenario: 子会话模型解析与切换
- **WHEN** 原生子会话恢复或在空闲时打开其模型选择菜单
- **THEN** 内部已绑定模型仍可解析，菜单使用当前 CLI 目录，保存不影响父会话或其他 Worker。

### Requirement: 缺失公开过程的真实说明
Grok 和 OMP 完成过程 SHALL 只对实际公开的思考、计划或工具记录提供内容展开。没有可读公开内容时 MUST 不在回复正文或轮次尾部插入“未提供公开思考”提示，不用正文、状态、token 计数或私密字段构造思考。

#### Scenario: Grok 返回公开思考
- **WHEN** 当前 Grok 原生协议或精确会话记录确实提供可读公开思考
- **THEN** 将其按真实顺序投影到原生过程并允许展开，正文独立显示，不重复累计。

#### Scenario: Grok 只返回正文和用量
- **WHEN** 当前 Grok 运行没有公开思考、计划和工具记录
- **THEN** 不添加缺失提示或伪造展开内容，已有真实用量和终态仍保留。

#### Scenario: OMP 公开过程与空思考
- **WHEN** OMP 返回可读公开思考、工具记录或仅空思考片段
- **THEN** 真实内容进入原生展开组；仅空片段不产生虚假内容，不把隐藏签名展示为思考。

### Requirement: 缺失用量与缓存的可检查状态
外部 CLI 的原生用量入口 SHALL 显示已核验的 token 与缓存统计；已绑定轮次但没有账单时消息功能条 SHALL 保留可查看的未知入口，缓存缺失时 SHALL 明示未知，不能用零或其他会话代替。累计、逐轮和上下文的口径保持独立，不能按上下文百分比反推 token 用量。

#### Scenario: Qoder 仅返回隐藏计数
- **WHEN** 当前 Qoder 回执只提供占位全零和上下文比例
- **THEN** 底部和精确绑定的消息用量入口均能查看未提供数据的状态，比例不转换成 token 数。

#### Scenario: Hermes 未报告缓存
- **WHEN** Hermes 有总用量但原始提供方没有报告缓存字段
- **THEN** 保留用量，缓存项显示未知；原生明确零、正数与缺失分别处理，不改写原始日志。

#### Scenario: 断连或身份不符
- **WHEN** 统计绑定不匹配、数据不完整或连接断开
- **THEN** 显示相应未知状态，不借用原生 Harness 包装调用量填充外部账单。

### Requirement: 每轮持久思考记录
CLI 子对话 SHALL 在原生思考过程内将已有公开思考行呈现为“思考记录”折叠入口，覆盖全部受支持 CLI。生成时保留原生公开摘要预览，完成、停止或失败后保留已经记录的公开文本，重开历史可再次展开。面板 MUST 跟随原生过程的展开/收起，按当前子会话和轮次隔离，保留原文和原始顺序，使用原生主题、安全 Markdown 和键盘操作；不得生成伪工具调用或重复保存文本。

#### Scenario: 全部 CLI 的公开内容
- **WHEN** 任一受支持 CLI 的当前轮已保存一段或多段公开思考
- **THEN** 结束后展开“已完成，用时…”的原生过程，可查看其中的“思考记录”；各段与工具按原始步骤顺序呈现，答复及功能条外不新增面板

#### Scenario: 流式完成和历史重开
- **WHEN** 原生公开摘要增量流式到达，随后本轮结束，用户关闭重开子对话
- **THEN** 生成时使用原生预览，完成快照覆盖同一段的增量而不重复，重开后仍可展开持久内容

#### Scenario: 未公开和未知
- **WHEN** 本轮只有正文、工具、空白、reasoning token 数、redacted、签名或加密数据
- **THEN** 不显示空的思考记录入口或缺失提示，不补造思考，不解码非公开字段

#### Scenario: 跨会话和交互
- **WHEN** 用户切换 Worker、查看主会话、用键盘展开收起或卸载插件
- **THEN** 不将其他轮次或 Worker 内容混入面板，主会话不新增此入口，键盘操作和主题正常，订阅及注册随所属生命周期清理

### Requirement: Codex 显式请求公开摘要
Codex 新轮次 SHALL 使用原生公开摘要请求选项，同时保持用户选择的模型、强度及权限。是否显示思考记录 MUST 以该轮实际返回的可读公开摘要为准，不读取 raw reasoning，不追溯改写没有摘要的历史。经核验的原生 Codex 公开摘要增量 SHALL 在运行中进入原生思考过程，不等待条目或整轮完成；完成、停止或失败后保留已公开内容且不重复。

#### Scenario: 新轮返回摘要
- **WHEN** Codex 新建或恢复原生会话并开始一轮
- **THEN** 请求自动公开摘要，按原生 item 和段落身份累计并保存实际返回内容，最终快照不重复展示

#### Scenario: 原生没有返回摘要
- **WHEN** 模型没有返回公开摘要，或正在查看历史无摘要轮次
- **THEN** 保留真实答复与统计，不显示虚构思考，不自动重跑模型

#### Scenario: 生成期间收到公开增量
- **WHEN** 当前 Codex 原生轮次收到公开摘要增量且仍未完成
- **THEN** 原生思考过程即时展示累计的公开文本，后续增量追加到同一记录，最终正文独立保留

#### Scenario: 摘要期间中断
- **WHEN** 已收到 Codex 公开摘要后用户停止或运行失败，最终摘要条目尚未完成
- **THEN** 保留已公开的摘要前缀，继续等待真实退出结果，不伪造完成内容或工具成功

#### Scenario: 未核验协议或其他运行
- **WHEN** 可撤回摘要快照来自未核验协议、旧 transport 或不属于当前 run
- **THEN** 保持原有完成门槛和运行隔离，不因支持 Codex 公开增量而提前展示其他来源
