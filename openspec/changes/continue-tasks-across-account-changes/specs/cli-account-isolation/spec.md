## MODIFIED Requirements

### Requirement: 账号绑定和执行重检
Host SHALL 以不含秘密的账号来源版本绑定目录与任务，在保存选型、启动、出队及续聊时重新检查。新派遣的选型在选型或排队期间遇到换号 MUST 不自动用于新账号。已有任务的后续轮次遇到换号时 SHALL 按「换号后自动续接」改绑当前账号。当前没有可用的自身账号，或所选模型、强度在当前账号下失效时，MUST 阻止任务，不能静默换模型或 CLI，也 MUST 不恢复旧账号凭据。同账号续期 SHALL 以当前原生来源仍存在且身份一致为前提。

#### Scenario: 选型与排队期间换号
- **WHEN** 用户回答新任务的选型期间或新任务首轮排队期间退出、换号或切换来源
- **THEN** 原选择不能自动用于新账号，提示重新选择或派遣

#### Scenario: 续聊与旧快照
- **WHEN** 原账号已经退出或换号，当前 CLI 已登录另一自身账号，且原模型与强度在当前账号下可用
- **THEN** 按「换号后自动续接」在当前账号下继续，不恢复旧账号或覆盖当前来源，不要求新建任务

#### Scenario: 已退出且无当前账号
- **WHEN** 续聊时该 CLI 没有已登录的自身账号
- **THEN** 拒绝启动并提示登录，历史可查看，不使用旧 Worker 中残留的凭据

#### Scenario: 历史任务没有账号绑定
- **WHEN** 升级前的历史任务没有可核验的原账号绑定
- **THEN** 视同换号，按「换号后自动续接」绑定当前账号续接；当前无可用账号时拒绝并提示登录

#### Scenario: 权限与强度撤销
- **WHEN** 账号未变或已改绑，但所选模型或强度在当前账号下不再可用
- **THEN** 启动前拒绝，不发送 prompt，不选择替代项，提示重新选择模型

#### Scenario: 同一次启动内来源竞态
- **WHEN** 一次启动的准备阶段与实际启动之间账号来源发生 A→B→A 或其他变化
- **THEN** 按准备快照核对并拒绝本次启动，不以改绑掩盖竞态

#### Scenario: 原生续期无法保护当前账号
- **WHEN** OpenCode OAuth 等原生续期缺少版本条件写回，无法阻止退出或换号后恢复旧凭据
- **THEN** 保留真实登录状态，该模式返回空目录并拒绝执行；同一 CLI 自身 API 配置仍可按当前账号范围开放

## ADDED Requirements

### Requirement: 换号后自动续接
已有任务的续聊、排队续聊、分支及子对话换模型遇到账号绑定变化时，Host SHALL 在当前 CLI 已登录自身账号、且原模型与强度经当前账号目录授权后，自动把任务改绑到当前账号并继续，MUST 不弹出确认。改绑 SHALL 在时间线记录一条不打断的说明，含当前账号的非秘密标签，不含凭据。运行中的进程 MUST 不因换号被改绑；换号后发送的运行中引导消息 SHALL 转为排队，在下一轮于当前账号下发送。

#### Scenario: 换到另一账号后续聊
- **WHEN** 任务原绑定账号 A，用户已在该 CLI 改登账号 B，B 下原模型与强度可用，用户发送续聊
- **THEN** 不提示用户，任务改绑 B 并续接；时间线显示「已改用当前账号继续」及 B 的标签

#### Scenario: 同一账号凭据格式变化
- **WHEN** 同一账号的原生凭据改写为新格式，导致绑定版本变化
- **THEN** 与换号同样自动改绑续接，不提示用户

#### Scenario: 排队中的续聊遇到换号
- **WHEN** 续聊排队期间用户换号
- **THEN** 出队时按当前账号重新授权后改绑执行，不因原绑定失效而丢弃排队消息

#### Scenario: 运行中换号并发送引导
- **WHEN** 本轮进程仍在运行，用户换号后发送引导消息
- **THEN** 该消息转为排队，本轮进程不受影响；下一轮在当前账号下发送

#### Scenario: 新账号下原模型不可用
- **WHEN** 换号后原模型或强度不在当前账号的授权目录中
- **THEN** 不改绑、不发送 prompt，按现有选型提示要求重新选择模型

### Requirement: 原生续接失败时自动改接
改绑后，Host SHALL 按 CLI 的跨账号续接方式表决定先尝试原生续接或直接改接。已确认无法续接，或不调用模型的本地预检确认原生会话不在当前账号将使用的会话存储中时，SHALL 直接改接，MUST 不先发起一次注定失败的原生续接。原生续接在产生任何回复或工具事件前失败时，Host SHALL 自动改接：在当前账号下为同一任务建立新的原生会话，以插件保存的此前对话公开记录作为有界上下文先行发送，再发送本次消息。上下文 MUST 标明来自插件历史且不是新指令，MUST 不额外调用模型生成摘要。已产生回复或工具事件后的失败 MUST 照常报告，不自动重试。用户停止时 MUST 不改接。

#### Scenario: 原生续接被拒
- **WHEN** 改绑后原生续接返回错误，且尚未产生回复或工具事件
- **THEN** 自动在当前账号建立新会话，附带此前记录并发送本次消息；任务保持为同一个，时间线说明已改接及附带的记录条数

#### Scenario: 已知无法续接
- **WHEN** 跨账号续接方式表标记该 CLI 无法跨账号续接，或预检发现原生会话不在当前账号的会话存储中
- **THEN** 不尝试原生续接，直接改接

#### Scenario: 已开始执行后失败
- **WHEN** 原生续接已产生回复或工具事件后失败
- **THEN** 报告本轮失败，不自动改接或重试，避免重复执行写操作

#### Scenario: 用户停止
- **WHEN** 用户在原生续接过程中停止任务
- **THEN** 等待进程范围清理确认后报告停止，不改接

#### Scenario: 历史超出上下文预算
- **WHEN** 插件保存的此前记录超过改接上下文预算
- **THEN** 保留最近的完整轮次和首轮用户需求，省略部分明确标注被省略的条数，不截断到半条消息
