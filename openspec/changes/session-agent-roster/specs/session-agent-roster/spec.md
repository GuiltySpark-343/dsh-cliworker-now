## ADDED Requirements

### Requirement: 会话级可用智能体的创建与命名
插件 SHALL 允许用户在当前会话内，从「智能体设置」的角色卡片创建一个或多个具体可用智能体，并为每个条目固定 CLI、模型、思考强度与角色提示词。条目 MUST 归属于创建它的会话，不跨会话共享；同一张卡片可创建多个条目，标题 MUST 在会话内唯一，默认按“卡片名 + 序号”分配，并与该会话已有 Worker 名称互斥。条目数量 MUST 有上限，超出时拒绝创建。

#### Scenario: 同一卡片创建多个条目
- **WHEN** 用户在会话 A 已有“项目执行者”条目的情况下再次从同一卡片创建
- **THEN** 新条目获得未被占用的编号标题（如“项目执行者2”），两个条目各自保存自己的 CLI、模型与强度

#### Scenario: 标题冲突
- **WHEN** 用户提交的标题与会话内已有条目或已有 Worker 名称重复
- **THEN** 保存被拒绝并返回明确原因，不覆盖、不合并已有条目

#### Scenario: 会话隔离
- **WHEN** 用户在会话 B 打开可用智能体列表
- **THEN** 只看到会话 B 自己的条目，会话 A 的条目不可见、不可派遣

### Requirement: 角色提示词来源
可用智能体的角色提示词 SHALL 默认跟随其来源卡片的当前内容；用户在该条目内编辑提示词后，该条目 MUST 转为使用自己的快照，并提供恢复跟随卡片的能力。来源卡片被删除时，条目 MUST 回落到最后一次保存的快照，而不是变为无角色或报错。

#### Scenario: 卡片更新后派遣
- **WHEN** 条目仍处于跟随状态，来源卡片的提示词被修改
- **THEN** 下一次派遣使用修改后的提示词，已创建的 Worker 保留各自创建时的角色快照

#### Scenario: 卡片被删除
- **WHEN** 条目来源卡片被删除后该条目被派遣
- **THEN** 使用条目最后一次保存的提示词快照完成派遣，并在条目上标明来源已删除

### Requirement: 模型清单只读已探测结果
可用智能体的模型与思考强度选项 SHALL 只来自「设置 → CLI 连接」已经探测并持久化的目录记录。该功能 MUST NOT 为此启动 CLI 进程、查询账号或发起网络请求；没有已保存记录时 MUST 提示用户先去设置完成探测，不得自行探测或用其他 CLI 的目录代替。

#### Scenario: 已有探测记录
- **WHEN** 用户为某 CLI 创建可用智能体，且该 CLI 在当前项目已有探测记录
- **THEN** 直接展示该记录中的模型与强度，表单默认值取该项目已保存的偏好

#### Scenario: 缺少探测记录
- **WHEN** 该 CLI 在当前项目从未探测过
- **THEN** 不显示任何模型选项、不启动 CLI，提示先到「设置 → CLI 连接」完成一次探测

### Requirement: 状态与执行次数投影
插件 SHALL 向主 Agent 提供一个只读查询，一次返回当前会话的可用智能体清单、各 Worker 的状态与已执行次数；该查询 MUST 不读取完整事件日志、不启动 CLI。Worker 每次开始新一轮时 MUST 累加并持久化执行次数，旧记录缺少该字段时按 0 处理。

#### Scenario: 派遣前查看全局状态
- **WHEN** 主 Agent 在派遣前调用状态查询
- **THEN** 返回可用智能体、各自对应的 Worker、运行状态与执行次数，足以判断谁空闲、谁在运行

#### Scenario: 无可用智能体
- **WHEN** 会话内没有任何可用智能体
- **THEN** 清单为空且不报错，行为与未引入该功能时一致

### Requirement: 提示词只做存在性提示
当会话存在可用智能体时，插件 SHALL 向主 Agent 的系统提示词注入一句简短提示，指向状态查询工具；该提示 MUST NOT 包含完整名单，且在没有条目时不得贡献任何文本。

#### Scenario: 名单变化
- **WHEN** 用户新增或删除可用智能体
- **THEN** 系统提示词只反映“是否存在可用智能体”，不随条目数量增长而变长
