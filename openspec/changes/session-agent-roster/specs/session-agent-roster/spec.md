## ADDED Requirements

### Requirement: 会话级可用智能体模板
插件 SHALL 允许用户在当前会话内，从「智能体设置」的角色卡片创建可用智能体模板，并为每个模板固定 CLI、模型、思考强度与角色提示词。模板 MUST 归属于创建它的会话，不跨会话共享；模板名称 MUST 在会话内唯一，并与该会话内未删除的 Worker 名称互斥。模板数量 MUST 有上限，超出时拒绝创建。

#### Scenario: 同一卡片建多个模板
- **WHEN** 用户已有一个「项目执行者」模板，再次从同一卡片创建并命名为「项目执行者-B」
- **THEN** 两个模板各自保存自己的 CLI、模型与强度，互不覆盖

#### Scenario: 标题冲突
- **WHEN** 用户提交的模板名称与会话内已有模板或未删除 Worker 名称重复
- **THEN** 保存被拒绝并返回明确原因，不覆盖、不合并已有条目

#### Scenario: 会话隔离
- **WHEN** 用户在会话 B 打开可用智能体列表
- **THEN** 只看到会话 B 自己的模板，会话 A 的模板不可见、不可派遣

### Requirement: 模板创建带编号的实例
模板 MUST 作为创建依据而不是具体实例：主对话按模板名称派遣时，插件 SHALL 每次创建一个新的 Worker，名称为「模板名 + 序号」（模板1、模板2…），并沿用模板固定的 CLI、模型、思考强度与角色。序号 MUST 取当前会话内该模板实例未被占用的最小数字；已删除（归档）的 Worker MUST 释放其名称，允许后续实例复用。派遣 MUST NOT 再弹出模型、思考强度或角色问题卡，也 MUST NOT 把模板与某个固定 Worker 绑定。

#### Scenario: 同一模板创建多个实例
- **WHEN** 主对话连续两次按「任务验收Agent」派遣
- **THEN** 创建「任务验收Agent1」「任务验收Agent2」两个独立 Worker，各自拥有独立 CLI 会话，配置都来自模板

#### Scenario: 删除后复用编号
- **WHEN** 「任务验收Agent1」被删除，随后再次按模板派遣
- **THEN** 新实例可以使用「任务验收Agent1」，已删除记录不再占用名称

#### Scenario: 模板与 CLI 不一致
- **WHEN** 主对话按模板派遣，但传入的 CLI 与模板固定值不同
- **THEN** 派遣在启动前被拒绝，错误说明模板固定的 CLI

#### Scenario: 模板不存在或参数冲突
- **WHEN** 传入的模板名不存在，或同时传入与模板冲突的模型/强度/角色
- **THEN** 派遣失败并给出原因，不创建 Worker

### Requirement: 角色提示词来源
模板的角色提示词 SHALL 默认跟随其来源卡片的当前内容；用户在该模板内编辑提示词后，模板 MUST 转为使用自己的快照，并提供恢复跟随卡片的能力。来源卡片被删除时，模板 MUST 回落到最后一次保存的快照。

#### Scenario: 卡片更新后派遣
- **WHEN** 模板仍处于跟随状态，来源卡片的提示词被修改
- **THEN** 之后创建的实例使用修改后的提示词，已创建的 Worker 保留各自创建时的角色快照

#### Scenario: 卡片被删除
- **WHEN** 模板来源卡片被删除后按该模板派遣
- **THEN** 使用模板最后一次保存的提示词快照完成派遣，并在模板上标明来源已删除

### Requirement: 模型清单只读已探测结果
模板的模型与思考强度选项 SHALL 只来自「设置 → CLI 连接」已经探测并持久化的目录记录。该功能 MUST NOT 为此启动 CLI 进程、查询账号或发起网络请求；没有已保存记录时 MUST 提示用户先去设置完成探测。

#### Scenario: 已有探测记录
- **WHEN** 用户为某 CLI 创建模板，且该 CLI 在当前项目已有探测记录
- **THEN** 直接展示该记录中的模型与强度，表单默认值取该项目已保存的偏好

#### Scenario: 缺少探测记录
- **WHEN** 该 CLI 在当前项目从未探测过
- **THEN** 不显示任何模型选项、不启动 CLI，提示先到「设置 → CLI 连接」完成一次探测

### Requirement: 状态与实例投影
插件 SHALL 向主 Agent 提供一个只读查询，一次返回当前会话的模板清单（含各自已创建的实例数量与名称）、各 Worker 的状态与已执行次数。该查询 MUST 不读取完整事件日志、不启动 CLI。Worker 每次开始新一轮时 MUST 累加并持久化执行次数，旧记录缺少该字段时按 0 处理。

#### Scenario: 派遣前查看全局状态
- **WHEN** 主 Agent 在派遣前调用状态查询
- **THEN** 返回模板、每个模板已创建的实例与运行状态，足以判断该复用哪个实例、该新建哪个模板实例

#### Scenario: 无模板
- **WHEN** 会话内没有任何模板
- **THEN** 清单为空且不报错，行为与未引入该功能时一致

### Requirement: 提示词只做存在性提示
当会话存在模板时，插件 SHALL 向主 Agent 的系统提示词注入一句简短提示，指向状态查询工具并说明 template 参数；该提示 MUST NOT 包含完整模板清单，且在没有模板时不得贡献任何文本。

#### Scenario: 模板变化
- **WHEN** 用户新增或删除模板
- **THEN** 系统提示词只反映“是否存在模板”，不随条目数量增长而变长
