## ADDED Requirements

### Requirement: 隔离副本开关
「CLI Worker 设置」→「任务调度」SHALL 提供「同目录写任务并行（隔离副本）」开关，默认关闭，保存在 Host 私有 `general-settings.json`，重启后保留。说明文字 MUST 为一行，讲清在项目副本中同时运行、完成后由主 Agent 合并；开关自身显示保存后的状态，保存成功 MUST NOT 另显确认文字。非布尔值 MUST 被拒绝且不改变已保存值。关闭开关 MUST NOT 影响已绑定副本的对话，它们仍需合并或丢弃。

#### Scenario: 打开并保存
- **WHEN** 用户在设置页打开开关
- **THEN** Host 保存 `isolatedParallelWrites: true` 并立即重新调度排队任务

#### Scenario: 非法值
- **WHEN** 补丁中的开关值不是布尔值或 `null`
- **THEN** 保存失败，原值不变

### Requirement: 副本创建与上限
副本 SHALL 位于插件私有状态目录的 `isolated/<Worker ID>/` 下，POSIX 目录 0700、元数据文件 0600。复制 MUST 使用参数数组的文件 API，不拼接 shell；支持时使用写时复制，否则普通复制。复制 MUST 排除 `.git` 及依赖、缓存目录；符号链接不跟随，仅复制相对且留在项目内的链接，其余跳过并记录。复制前 MUST 统计文件数与体积，超出上限时不复制任何内容，任务回退为原有排队，并在任务卡写明原因。Host MUST 为每个复制的文件记录哈希，并为可三方合并的文本保存基线内容。副本路径 MUST 通过专门校验：必须是该 Worker 在插件根下的确切目录，且不是符号链接；项目路径的凭据目录校验 MUST 保持不变。

#### Scenario: 超出上限
- **WHEN** 项目文件数或体积超过上限
- **THEN** 不创建副本，任务排队等待主目录，任务卡显示超限原因

#### Scenario: 项目外的符号链接
- **WHEN** 项目内有指向项目外或使用绝对路径的符号链接
- **THEN** 副本中不包含该链接，也不复制其目标内容

#### Scenario: 创建中取消
- **WHEN** 用户在副本创建过程中停止任务
- **THEN** 已复制的部分被删除，任务以用户停止结束，不启动 CLI

### Requirement: 副本中运行
Worker 的项目身份（父会话、项目偏好、权限模式）SHALL 保持为原项目；CLI 的实际工作目录、原生目录参数及账号核验 SHALL 使用副本路径，按各 CLI 现有参数构建器生成，不套用其他 CLI 的开关。本轮提示 MUST 告知 CLI 当前在副本中运行、原项目路径不可写、副本不含 `.git` 与依赖目录。隔离运行 MUST NOT 接通 DSH 工具桥。合并或丢弃之前，该对话的续聊与恢复 MUST 回到同一副本；之后续聊 SHALL 在同一路径重新建立副本，无法建立时如实失败，不改回主目录。

#### Scenario: 合并前续聊
- **WHEN** 隔离对话完成后用户在合并前继续发送消息
- **THEN** CLI 在同一副本路径恢复原会话，不在主目录运行

#### Scenario: 合并后续聊
- **WHEN** 隔离对话已合并，用户继续发送消息
- **THEN** Host 在同一路径重新复制当前主目录作为新基线，再恢复原会话

### Requirement: 合并
Worker 空闲（不在运行、准备、排队或停止中）且副本存在时，主 Agent SHALL 通过 `cliworker_merge` 合并；任务卡 MUST NOT 显示副本状态行或「合并」「丢弃」按钮。隔离任务完成通知与 `cliworker_status` MUST 告诉主 Agent 改动仍在副本、主目录未改动、核查后调用 `cliworker_merge`，且不要让 CLI 改到原目录重做。合并 MUST 逐文件三方比较：只有副本改动的直接写回；两边都改动的文本做 diff3；二进制、类型改变、删除对修改、仅大小写不同的改名或无法自动合并的文本算冲突。新增、删除与改名（视为删除加新增）都要处理，可执行位随副本改动。未决定的冲突存在时主目录 MUST 一个文件都不写。全部成功时 MUST 以未提交改动写回并清理副本，绝不执行提交。写回 MUST 拒绝越出项目或经过符号链接的路径。主目录有写任务运行时 MUST 拒绝合并。

#### Scenario: 仅副本改动
- **WHEN** 副本修改、新增或删除了主目录未改动的文件
- **THEN** 这些改动写回主目录，副本被清理

#### Scenario: 两边改动可合并
- **WHEN** 同一文本文件两边改动了不重叠的行
- **THEN** 合并结果同时包含两边改动

#### Scenario: 主目录有写任务
- **WHEN** 同项目主目录中有写任务正在运行
- **THEN** 合并被拒绝并提示稍后重试

### Requirement: 冲突由用户决定
出现无法自动合并的文件时，`cliworker_merge` MUST 通过原生询问由用户逐个决定：「采用 CLI 副本的版本」「保留项目当前版本」「暂不合并」；结构性冲突（特殊文件、越界链接、类型改变、仅大小写改名、主目录路径不安全）只提供后两项。冲突超过 6 个时 MUST 改为一次性询问（全部采用副本 / 全部保留项目 / 暂不合并），结构性冲突仍保留项目版本。每个冲突都有决定前，主目录 MUST 一个文件都不写、不写冲突标记；用户暂不合并、未作答或只填写自由文本时 MUST 保留副本并把决定或说明返回主 Agent，自由文本不作为合并决定执行。

#### Scenario: 冲突询问用户
- **WHEN** 两边改动同一行，或改动同一个二进制文件
- **THEN** 写回前向用户询问该文件采用哪一版；作答前主目录没有任何文件被修改

#### Scenario: 用户逐个决定
- **WHEN** 用户对每个冲突选择副本或项目版本
- **THEN** 按决定写回或保留，其余改动照常写回，副本被清理

#### Scenario: 暂不合并
- **WHEN** 用户选择暂不合并或未作答
- **THEN** 主目录没有任何文件被修改，副本保留，结果列出冲突文件

#### Scenario: 结构性冲突
- **WHEN** 副本把文件改成目录，或新增指向项目外的链接
- **THEN** 询问只提供保留项目当前版本或暂不合并

### Requirement: 丢弃
主 Agent 工具 `cliworker_discard` SHALL 在执行前通过原生询问取得用户确认；只有副本目录确认删除后才报告成功。丢弃不改动主目录。

#### Scenario: 确认后丢弃
- **WHEN** 用户确认丢弃
- **THEN** 副本目录被删除并报告成功，主目录不变

#### Scenario: 取消确认
- **WHEN** 用户在确认时选择取消
- **THEN** 副本保留，不报告成功

### Requirement: 生命周期与恢复
副本元数据 SHALL 随 Worker 记录持久化。Host 重启时，创建中的副本 MUST 被删除并解除绑定；合并中断的副本 MUST 恢复为可再次合并的状态；已就绪或有冲突的副本 MUST 保留。停止只结束进程，不删除副本；删除（归档）Worker 保留副本以便恢复；合并、丢弃进行中时 MUST 拒绝发送、删除等冲突操作。界面只显示真实状态，不显示伪造进度。

#### Scenario: 重启恢复
- **WHEN** Host 在副本已就绪后重启
- **THEN** 主 Agent 仍可合并或丢弃，续聊回到同一副本

#### Scenario: 创建中重启
- **WHEN** Host 在复制过程中退出后重新启动
- **THEN** 不完整的副本被删除，Worker 不再绑定该副本
