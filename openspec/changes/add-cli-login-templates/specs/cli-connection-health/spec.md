## ADDED Requirements

### Requirement: 可复用登录模板窗口
各 CLI 的登录与退出 SHALL 使用插件绘制的分步窗口，由可复用模板组合而成（信任文件夹、选项、浏览器授权、浏览器授权加授权码、设备码、API Key/PAT、确认中、结果）；原生终端在后台运行、默认隐藏并可由用户显示。Host SHALL 按每个 CLI 的流程定义识别原生画面，窗口文案与选项标签由插件固定提供，MUST 不转发或渲染 CLI 输出；用户提交的授权码与密钥 MUST 只写入原生终端，不进入事件、日志或引导帧。登录与退出结果 MUST 以原生账号状态确认。「账号终端」保持原生终端。

#### Scenario: 浏览器授权自动完成
- **WHEN** 原生流程显示登录地址并等待浏览器完成授权
- **THEN** 窗口显示「在浏览器中授权」及（白名单地址才有的）重新打开/复制链接，原生账号状态变为已登录后显示成功并结束终端

#### Scenario: 设备码
- **WHEN** 原生流程显示验证地址与设备码
- **THEN** 窗口大字显示设备码并可复制、打开白名单地址，等待原生状态确认

#### Scenario: 密钥输入
- **WHEN** 原生流程请求 API Key 或 PAT
- **THEN** 窗口显示密码型输入框；提交后经 Host 写入原生终端并清空输入框，密钥不出现在引导帧和事件中

#### Scenario: 选项由用户决定
- **WHEN** 原生流程显示登录方式或平台菜单
- **THEN** 窗口显示插件固定标签的选项，用户点击后 Host 才写入对应按键；Host 拒绝不属于当前步骤的回应

#### Scenario: 无法识别的画面
- **WHEN** 画面静止 8 秒仍未匹配任何步骤且不在等待授权
- **THEN** 窗口提示在原生终端继续并展开终端，此后不再自动写入

#### Scenario: 确认超时
- **WHEN** 提交后限定时间内原生账号状态未变化
- **THEN** 显示未确认原因，提供重新开始与显示原生终端，不以终端文字判定成功

### Requirement: 登录来源下拉框
有多个可登录服务商的 CLI SHALL 在登录窗口顶部提供「登录到」下拉框，选项由 Host 按当前安装版本提供并标注已登录者。Host SHALL 只用 CLI 自身参数定位所选服务商；没有对应参数的服务商 MUST 不由插件在原生菜单中代选，改为在原生终端中由用户选择。ZCode 的 BigModel/Z.AI 选择并入下拉框。

#### Scenario: 以参数定位
- **WHEN** 用户选择的服务商可由原生参数指定
- **THEN** 以该参数启动原生登录，不先显示原生服务商菜单

#### Scenario: 原生菜单由用户选择
- **WHEN** 服务商只能在原生菜单中选择（下拉框中的「其他服务商」，或尚无参数的 CLI）
- **THEN** 启动原生登录并显示原生终端，由用户在菜单中选择；插件不写入方向键或回车代选

### Requirement: 多账号登录与切换
单账号 CLI 已登录时，登录窗口 SHALL 显示当前账号并提供「切换账号」，先自动退出并经原生状态确认后才进入登录；退出未确认 MUST 不继续登录。多服务商 CLI 选择已登录服务商时 SHALL 提示将替换其现有凭据；支持同服务商多凭据的 CLI SHALL 让用户选择添加另一个账号或替换。插件 MUST 不替任务挑选具体凭据。

#### Scenario: 切换单账号
- **WHEN** 用户在已登录的单账号 CLI 点击「切换账号」
- **THEN** 自动退出确认后进入登录向导；旧任务按换号续接规则处理

#### Scenario: 同服务商添加账号
- **WHEN** 用户在 Hermes 选择已登录服务商并选「添加另一个凭据」
- **THEN** 保留原凭据并新增一个，确认以该服务商凭据数增加为准

#### Scenario: 替换确认
- **WHEN** 用户选择已登录服务商且操作会替换其凭据
- **THEN** 先显示替换提示，用户确认后才启动原生登录

### Requirement: 账号窗口与逐个退出
多账号 CLI SHALL 提供「账号」窗口，列出已登录账号（服务商、登录方式、可安全显示的邮箱），原生支持单项退出的每行可单独退出，并提供「添加账号」。逐个退出 SHALL 先行内确认，再由 Host 以该 CLI 支持的单项退出方式自动完成，并以目标条目从原生状态中消失为准；MUST 不提供一键全部退出，其他账号保持不变。原生不支持单项退出时 SHALL 如实说明并交给原生终端。

#### Scenario: 退出一个账号
- **WHEN** 用户在账号窗口确认退出某一行
- **THEN** Host 只退出该条目，确认消失后该行移除，其他行不变

#### Scenario: 只能一起退出
- **WHEN** 原生只能同时退出一组账号（如 ZCode 的 BigModel 与 Z.AI）
- **THEN** 该组显示为一行并写明会一起退出

#### Scenario: 尚未接入逐条退出
- **WHEN** CLI 的单条退出尚未接入（Kimi、Pi、OMP）
- **THEN** 账号行写明「在原生终端中退出」，由用户在原生菜单中选择，不显示伪装的逐行退出

#### Scenario: 退出未确认
- **WHEN** 限定时间内目标条目仍在
- **THEN** 该行显示未确认并提供显示原生终端，不重复写入

## MODIFIED Requirements

### Requirement: 一致的原生退出入口
OMP、Pi 和 Hermes 已登录时 SHALL 提供与其他 CLI 一致的退出入口，并接入各自当前原生支持的退出流程。仅打开设置 MUST 不退出账号；用户明确选择退出后才进入对应原生操作，不能用禁用占位按钮伪装成可用功能。退出和取消 SHALL 保持现有自身来源、账号互斥、模型失效与进程清理语义。多账号 CLI 的退出入口为「账号」窗口中的逐行退出。

#### Scenario: 自身账号退出
- **WHEN** 用户在 OMP、Pi 或 Hermes 的账号窗口退出某一行
- **THEN** 进入该 CLI 原生退出流程；不使用另一 CLI 的命令、不自动退出其他来源或删除账号目录

#### Scenario: 多个自身来源
- **WHEN** CLI 同时有原生目录与插件目录中的账号
- **THEN** 账号窗口在列表下方按来源提供原生退出入口；退出只操作所选来源，不删除合并副本后再从原来源恢复，其他来源仍有效时如实保留登录状态

#### Scenario: 账号使用中或关闭终端
- **WHEN** 账号正被任务占用，或用户取消退出界面
- **THEN** 冲突操作被拒绝；关闭需等待进程范围清理，未提交退出时原有账号保留

#### Scenario: 原生抑制保留的配置
- **WHEN** Hermes 的原生退出将当前配置来源标为 suppressed 而保留其原值
- **THEN** Host 按当前同源标记停止将其用于认证、目录和执行，不从保留值恢复已退出账号；其他未抑制来源仍按原生规则核对
